# Аудит PPO-эксперимента

Проверять возможность обоснованного сравнения двух видов регуляризации, а не подтверждать предполагаемое преимущество одного из них. Соблюдать правила Colab и статусов выполнения из `../../../AGENTS.md` относительно папки скилла. Если этот файл недоступен, всё равно выполнять вычислительные эксперименты только в Google Colab и не заявлять о запуске без свидетельств.

## Исходные свидетельства

Изучить существующие инструкции, функции среды и reward, подготовку данных, конфигурации PPO, ноутбуки и доступные артефакты. Найти реальные места реализации до предложения нового кода. Если реализации ещё нет, выдать аудит протокола и требования к проверкам, не отчёт о выполненном эксперименте.

Восстановить цепочку: доступные данные → наблюдение → коэффициент штрафа → действие → исполнение → доходность и издержки → reward → обновление PPO. Зафиксировать индекс времени и смысл каждого перехода. Неуказанные даты, формулы и конвенции обозначить как неизвестные.

## Что проверять

### Дизайн и сопоставимость

- Явно определить гипотезу, основную финансовую метрику, фиксированный коэффициент и формулу адаптации. Найти, где штраф включён: в reward среды или непосредственно в loss PPO; проверить знак, масштаб, единицы и отсутствие повторного вычитания.
- Различать регуляризацию оборота, entropy bonus, PPO clipping и комиссии. При reward вида `r_net - lambda_t * turnover_t` проверить, что `r_net` уже содержит реальные моделируемые издержки ровно один раз, а финансовые метрики не используют штрафованный reward вместо доходности.
- Сверить по конфигурациям одинаковые universe, календарь, цены, обработку пропусков, признаки, стартовый капитал, наличность, начальные позиции, ограничения, частоту ребалансировки, исполнение, комиссии и проскальзывание. Различия перечислить и оценить как потенциальные смешивающие факторы.
- Проверить архитектуру, PPO-гиперпараметры, нормализацию reward, число шагов среды, seed, критерий остановки, выбор чекпойнта и бюджет поиска. Обеспечить сопоставимый бюджет настройки каждого метода; не требовать одинаковых оптимальных коэффициентов. Общий контроль без штрафа или простые бенчмарки предлагать как обоснованные дополнения, не выдавать за уже выполненные опыты.

### Причинность и независимость теста

- Для каждого признака, цены исполнения и `lambda_t` установить момент фактической доступности. Использование close дня t для сделки по тому же close требует обоснованной модели исполнения; иначе сдвинуть решение/исполнение. Проверить forward-fill, backfill, центрированные окна, отрицательные shift и глобальные агрегаты.
- Обучать scaler, imputer, feature selection и параметры адаптации только на допустимой обучающей истории. При оценке замораживать обучаемые статистики нормализации и веса политики; причинное обновление скользящей волатильности допустимо, если предусмотрено протоколом. Для онлайн-переобучения нужен отдельный одинаковый причинный протокол для обеих стратегий.
- Проверить хронологические train/validation/test и даты всех эпизодов. Исключить переходы reward и целевые горизонты, пересекающие запрещённые границы; gap/purging выбирать по горизонту перекрытия, не произвольно. Предшествующая история для lookback теста допустима, если к моменту решения уже известна и не используется для подгонки на тесте.
- Тест не должен выбирать коэффициент, формулу адаптации, seed, чекпойнт или раннюю остановку. Для walk-forward проверить вложенную настройку и независимость каждого OOS-интервала; пересекающиеся OOS-даты не считать независимыми наблюдениями.
- Проверить survivorship bias, делистинги, корпоративные действия, состав индекса и задержки публикации. Современный список акций и ретроспективно пересчитанные данные не считать автоматически point-in-time; ограничения источника раскрывать.

### Реализованная волатильность и адаптация

- Требовать точную формулу, источник (актив, портфель или рынок), частоту доходностей, длину окна, единицы и правило годового масштабирования. Различать сумму квадратов внутрипериодных доходностей `RV = sum(r_j^2)`, её корень и rolling standard deviation; не называть эти величины взаимозаменяемыми. Дневную rolling-оценку описывать по фактическому определению.
- Проверить, что все входящие доходности завершились до решения. Если доступна последняя завершённая доходность t, она может входить в оценку для последующего исполнения; величина t+1 не может определять действие t. Не добавлять shift механически без проверки принятой индексации.
- Проверить warm-up, минимальное число наблюдений, NaN, нулевую волатильность, epsilon, clipping, `ddof` при стандартном отклонении и масштаб коэффициента. Параметры fallback и пороги оценивать без тестовых данных; не заполнять начало окна будущими значениями.
- Для портфельной волатильности проверить причинное происхождение весов. Если коэффициент зависит от собственных прошлых результатов стратегии, явно описать эту обратную связь. Логировать оценку волатильности, `lambda_t`, оборот, reward и net returns раздельно.

### Воспроизводимость в Colab

- Подготовить чистый последовательный запуск ноутбука: установка зафиксированных зависимостей, получение версии данных, конфигурация, seed, обучение, сохранение, независимая оценка. Исключить зависимость от скрытого состояния ячеек и локальных абсолютных путей.
- Сохранять run ID, commit либо хеш исходников, конфигурацию, версии/хеши данных и разбиения, seed Python/NumPy/фреймворка/среды, версии библиотек и оборудования Colab. Фиксировать ограничения детерминизма, режим оценки и правило выбора модели.
- Предусмотреть устойчивое сохранение чекпойнтов, статистик нормализации, журналов, временных рядов и истории неудачных запусков вне эфемерного runtime. Секреты и учётные данные в репозиторий не помещать.
- Подготовить для Colab проверки причинности: изменение будущих данных не меняет прошлые признаки/действия при фиксированной политике; fit препроцессора не видит тест; пары вариантов имеют одинаковые условия; волатильность на простой последовательности совпадает с ручным расчётом. Не утверждать, что проверки прошли, до фактического запуска.

## Результат аудита

Указать область и статус проверки, изученные версии и недостающие артефакты. Для каждого существенного замечания дать: критичность, свидетельство, влияние на сравнение, конкретное исправление и способ проверки в Colab. Разделять блокирующую недостоверность сравнения, ограничения интерпретации и необязательные улучшения. Завершить перечнем условий, которые ещё нужны для научного вывода; не считать статический обзор подтверждением воспроизводимости обучения.

Если задача включает финансовые формулы и статистические выводы, дополнительно применить соседний `../financial-backtesting/SKILL.md`.
