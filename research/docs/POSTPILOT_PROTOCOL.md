## 1. Независимая проверка идентичности

Notebook 05 выполняется в новой управляемой сессии Colab. Полный pytest текущего
evaluator — в subprocess до реальных данных. Development loader открывает
только validation с границей ценовой истории до 2022-01-01.

Для всех 27 моделей проверяются:

1. Batch, metadata sidecars, run/checkpoint SHA256, source test gate,
   конфигурации, training SHA, data contract, Python и версии библиотек.
2. Исполнение исходных действий на всех 757 датах и точное совпадение финансов.
3. Новые действия на исходных состояниях и точное совпадение с исходными действиями.
4. Полная новая закрытая траектория и точное совпадение таблиц/метрик с исходными.
5. Две независимые загрузки внутри новой сессии и точное совпадение между ними.

CPU threads=1, inter-op threads=1, deterministic algorithms=True; записываются
PyTorch build, CPU capability и matmul precision. Каждый exact-флаг хранится
отдельно; максимальные отклонения действий/NAV — диагностика. Допусков и
приблизительного passed нет. `diagnostic_complete` при любом расхождении
блокирует seal/test; `exact_replay_passed` требует всех exact-флагов всех 27 моделей.
Хеши и успешная загрузка не заменяют проверку фактических результатов.

Независимость подтверждается явным действием пользователя и записью kernel/boot
identity. Исходный training boot ID не сохранялся, поэтому машинное доказательство
независимости не заявляется. При неуспехе исследовать различия, не переобучать
модели и не подбирать допуски. Изменение политики приёмки потребует отдельного
решения до test; автоматического обхода gate нет.

## 2. Парный validation-анализ и оборот

Используются исходные проверенные `validation_financials.csv` выбранных девяти
моделей, не изменившиеся replay-результаты. Метрики вычисляет существующая
`financial_metrics`: Net Sharpe, CAGR, максимальная просадка как положительная
потеря, средний дневной оборот, суммарные комиссии. K=252, rf=0, ddof=1.

Для одинаковых seeds формируются adaptive−fixed, fixed−none и adaptive−none:
исходные значения, парные разности, среднее/sample std разностей и числа их знаков.
Для Sharpe/CAGR больше лучше; для просадки/оборота/комиссий меньше лучше.
Три seeds — малая выборка; sample std не является доверительным интервалом.

**Общий порог до test:** high, если причинная SPY sigma_t > train sigma_ref;
иначе low. Прежний RMS 20 завершённых log returns и train median не меняются.
Порог не выбирается по quantiles validation/test. Маски/даты общие для всех моделей.
По режимам выводятся число дат, условный Net Sharpe, средний оборот,
суммарные комиссии и средний lambda_t. Условный Sharpe описывает распределение
дневных доходностей режима с множителем sqrt(252), не отдельную непрерывную стратегию.
CAGR/просадка для разрывных подмножеств не вычисляются: склейка дней меняет путь.
Полные CAGR/drawdown представлены по целому периоду каждого seed.

Механизм: разность оборота adaptive−fixed в high/low и взаимодействие
`(adaptive−fixed)_high − (adaptive−fixed)_low`. Отрицательное взаимодействие
соответствует более сильному относительному снижению оборота в high.
Сам знак не доказывает причинность: одновременно меняются политика, состояние
портфеля и рынок. Более высокий lambda_t не гарантирует меньшего фактического оборота.

## Временная неопределённость

Парный stationary circular bootstrap: 2000 повторов, seed=20261108, ожидаемая
длина блока 20 дней; заранее предусмотрены sensitivity 10/40. Длины геометрические,
вероятность нового старта 1/L, старт равномерный, продолжение циклическое.
Реализация на NumPy, без новой зависимости arch.

Один набор временных индексов каждого повтора применяется ко всем режимам/seeds,
доходностям, обороту и режимным меткам. Пересчитываются Sharpe каждой политики
и **средняя парная разность Sharpe по трём seeds**. Seeds не ресэмплируются;
«дни × seeds» не объединяются в независимую выборку. Аналогично оцениваются
разности оборота high/low и взаимодействие. Номинальные 95% percentile интервалы
выводятся отдельно для каждой L; не выбирать удобную L по знаку результата.
Невалидные повторы не удаляются молча: при неопределённом Sharpe/пустом режиме
интервал получает статус undefined. Нулевая дисперсия не даёт конечного Sharpe.

Интервалы условны на конкретные политики и три seeds. Они характеризуют временную
неопределённость при допущениях bootstrap, не моделируют обучение/действия на новом
рынке и не устраняют структурные сдвиги/смещение выбора. Validation использовалась
для выбора, поэтому все её интервалы разведочные.

На test **одна основная оценка**: adaptive−fixed, весь период, средняя парная
разность Net Sharpe, основной L=20; L=10/40 — sensitivity. Сравнения с none,
режимные метрики и механизм оборота — вторичные описательные оценки.
Одновременной корректировки интервалов и p-values нет; нельзя объявлять набор
вторичных результатов подтверждённым семейством независимых гипотез.
IID t-test по day×seed и самостоятельного теста случайности обучения здесь нет.

## 4. Test 2022–2025

Notebook 06 открывает test при ENABLE_TEST=True, успешном новом pytest,
правильном заранее записанном lock SHA256, неизменных evaluator/source/data/model
hashes и том же runtime. TrainingConfig остаётся validation-only; отдельный
явный параметр inference разрешает test после gate. Обучение/development loader
по-прежнему запрещают test.

Перед чтением test создаётся постоянная отметка
`stage6/test_evaluations/<LOCK_SHA256>/test_access.json`. Каждая попытка получает
собственную папку `attempts/<id>/`; частичные/неудачные попытки не удаляются.
Технические повторы допустимы только с тем же lock, evaluator и конфигурациями.
Основной результат — первая полная попытка, указанная в `first_complete.json`;
последующие повторы являются диагностикой воспроизводимости, не новыми seeds
и не дополнительными кандидатами. Нельзя выбрать повтор с лучшей метрикой.

Повторно применяются прежние проверки causal features, corporate actions/
synthetic prices, train-only sigma_ref. Ожидаемый диапазон исходного Stage 1:
2022-01-03 — 2025-12-31, 1003 решения. Каждая модель начинает с cash=1000 без
переноса validation-позиций, с прежними комиссиями и frozen train-нормализацией.
Только final checkpoints. Две загрузки внутри новой сессии сравниваются точно.
Сохраняются все девять путей, метрики, парные/режимные таблицы и интервалы.

После test нельзя изменять гиперпараметры, seeds, выбор модели, метрики,
порог режимов или статистический метод на основании его результатов.
Следующее исследование требует отдельного протокола и не является подтверждением
на использованном holdout. Ограничения survivorship bias, ретроспективных
adjusted prices и отсутствия slippage/impact сохраняются.

## Запуск и артефакты

1. Опубликовать новый evaluator. Открыть notebook 05 из его SHA, указать этот
   полный SHA в GIT_REF. Новая независимая CPU-сессия, Colab 2026.07 / Python 3.12.
   MODEL_GIT_SHA и BATCH_ID исходного пилота оставить прежними.
2. RUN_TESTS=True, RUN_REPLAY=True, INDEPENDENT_SESSION=True,
   RUN_ANALYSIS=True, SEAL_DECISIONS=True. Выполнить сверху вниз.
   При неидентичном replay анализ допустим, но seal/test остаются заблокированы.
3. Прислать всю `stage5/sessions/<SESSION_ID>/`: session report/sidecar,
   pytest log/XML/gate, environment/pip freeze/check, provenance,
   replay report/sidecar и сравнения/траектории 27 runs, analysis CSV/report,
   decision lock/sidecar, если создан, и вывод последней ячейки.
4. После успешного seal записать SHA256 вне Drive. В новой сессии открыть
   notebook 06 из **того же evaluator SHA**, заполнить DECISION_SESSION_ID,
   LOCK_SHA256, RUN_TESTS=True, ENABLE_TEST=True. Выполнить сверху вниз.
5. Для приёмки test прислать `stage6/sessions/<id>/` и весь
   `stage6/test_evaluations/<LOCK_SHA256>/`: отчёты/sidecars, девять путей,
   метрики, paired/regime tables и bootstrap intervals.
   Старым runs не присваивать fresh-session passed вручную: новые свидетельства отдельные.
