## Предварительный обязательный шаг: публикация исходников

При подготовке инструкции GitHub вернул `research/AGENTS.md` из `main`, но для notebook этапа 1 вернул 404. Локально файлы этапа 1 ещё не отслеживаются Git. Поэтому обычное клонирование текущего `main` пока не содержит эту реализацию. Код в GitHub в рамках данной проверки не публиковался.

После просмотра изменений выполнить из корня локального `Science_Paper`:

```powershell
git add research/src research/tests research/notebooks/01_data_preparation.ipynb research/docs/METHODOLOGY.md research/docs/STAGE1_VALIDATION.md research/requirements-colab.txt
git commit -m "Prepare Stage 1 data pipeline and Colab validation"
git push origin main
git rev-parse HEAD
```

Если работа ведётся в другой ветке, опубликовать её и указать соответствующий ref; не перезаписывать чужую ветку принудительно. Проверить в GitHub, что выбранный commit содержит notebook с `stage1_revision=stage1-colab-validation-v2`, `src/validation.py` и все три файла тестов.

## Первый запуск

1. В Colab открыть notebook из GitHub `Go9shi/Science_Paper`, путь `research/notebooks/01_data_preparation.ipynb`, из опубликованного commit. Допустима загрузка того же `.ipynb` вручную. Исходные модули всё равно получает первая ячейка из GitHub.
2. До подключения выбрать `Runtime → Change runtime type → CPU → Runtime Version: 2026.07` и создать новую сессию. [Официальный список Colab](https://research.google.com/colaboratory/runtime-version-faq.html) указывает Python 3.12 для этой версии. Default runtime с Python 3.13 не подходит текущим pins; Python не понижать установкой pip-пакета. Локальный runtime не использовать. В первой ячейке задать `GIT_REF` равным опубликованному SHA; `GITHUB_REPOSITORY` по умолчанию уже задан.
3. Для публичного репозитория оставить `USE_GITHUB_SECRET=False`. Для private добавить Colab Secret `GITHUB_TOKEN` с правом чтения Contents, разрешить notebook доступ к нему и включить флаг. Не присылать секрет, не вставлять его в URL/текст ячейки.
4. Оставить `SNAPSHOT_ID="daily-v1"` либо задать новый ID, если snapshot уже существует с другой конфигурацией. Подключить Drive интерфейсом Google.
5. Выполнить установку и проверки импортов. При несовпадении загруженных версий перезапустить сеанс и начать сверху. Прямые версии/импорты обязательны; лог общего `pip check` изучить отдельно. Конфликт предустановленного неиспользуемого пакета не означает автоматически отказ pipeline и не должен скрываться.
6. Выполнить остальные ячейки по порядку. При ошибке не обходить проверки. Сохранить полный traceback, RUN_ID/путь preflight и соответствующие логи.

| Проверка | Требуемое свидетельство |
|---|---|
| Код и среда | SHA выбранного commit; исходники и Git bundle сохранены; прямые версии совпадают; импорты внутри checkout |
| Drive | Проба записи/чтения прошла; артефакты доступны после завершения runtime |
| Все тесты до котировок | pytest exit code 0; JUnit содержит cases; failures=errors=skipped=0; лог сохранён |
| Snapshot | 12 акций и SPY; vendor-таблицы сохранены; конфигурация и SHA-256 совпадают |
| Календарь/качество | Полное покрытие NYSE-сессий; нет дубликатов в доставленных таблицах, пропущенных/невалидных баров; нет imputation/inner-join удаления строк |
| Признаки | Доходности в наблюдении с lag=1; sigma заканчивается t−1; только полные окна; нет NaN в study features |
| Splits | Непересекающиеся train 2010–2018, validation 2019–2021, test 2022–2025; точное покрытие study-периода |
| Reference | Сохранённая sigma_ref совпадает с медианой только train sigma__SPY; test не выбирает параметры |
| Контракт цен | Close/Open/Adj Close и события разделены; factor-аудит доступен; execution_accounting_validated=false раскрыт |
| Read-back | Файлы прочитаны с Drive, подготовка воспроизведена из snapshot, значения/даты совпадают |
| Финал | validation_report.json: verified; metadata.json: complete; metadata.sha256 и файловые хеши совпадают; выведены counts/ranges/paths |

Ненулевые unexplained factor changes и конфликты общего `pip check` не скрываются. Технический `complete` не означает, что они объяснены человеком: перед научной приёмкой просмотреть их и записать решение/ограничение. Ошибка данных может потребовать новой версии snapshot/протокола; test нельзя использовать для выбора выгодной обработки.

## Что успешный этап 1 не доказывает

Survivorship/selection bias современного universe и ретроспективные корректировки Yahoo сохраняются. Snapshot — результат preprocessing yfinance, не исходный HTTP и не point-in-time архив. Синтетические тесты не подтверждают качество реальных данных без запуска проверок. Бухгалтерия split/dividend/cash и Open-исполнения не валидирована, PPO не обучался, эффективность не оценивалась. Статус «результат проверен по артефактам» возможен только после изучения фактического каталога Colab-запуска.
