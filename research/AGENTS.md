# Правила научного проекта

## Предмет исследования

Сравниваем фиксированный и адаптивный регуляризационные штрафы за торговый оборот в PPO-стратегиях управления портфелем акций. Не предполагать заранее преимущество адаптивного штрафа. Различать гипотезу, описание реализации и эмпирический результат.

## Среда и достоверность выполнения

- Все вычислительные эксперименты, обучение, подбор гиперпараметров и бэктесты выполняются исключительно в Google Colab. Codex подготавливает и проверяет код и ноутбуки; не запускает эксперименты локально и не заменяет Colab другой средой без изменения требования пользователем.
- Локально допустимы статический анализ, проверка структуры и синтаксиса, валидация инструкций. Численные тесты и проверки финансовой логики подготавливать для запуска в Colab; явно сообщать, если они не выполнены.
- Для каждого отчёта различать: «подготовлено», «проверено статически», «выполнено в Colab» и «результат проверен по артефактам». Наличие кода, старого вывода ячеек или чекпойнта само по себе не доказывает выполнение текущей версии.
- Утверждать о состоявшемся запуске только при наличии связанных с ним свидетельств: идентификатор запуска, версия кода и конфигурации, журнал выполнения и результаты. Указывать, какие артефакты изучены и что осталось непроверенным. Не выдумывать метрики, логи, p-value, доверительные интервалы и источники.

- Для аудита доходностей, оборота, издержек, финансовых метрик и статистических выводов читать [.agents/skills/financial-backtesting/SKILL.md](.agents/skills/financial-backtesting/SKILL.md).
- Для полного аудита эксперимента применять оба скилла; объединять общие замечания, не дублировать их. Не загружать оба автоматически ради правки, не затрагивающей эти вопросы.

## Научная корректность

- Перед изменениями изучать существующие инструкции, код и ноутбуки. Переиспользовать реализацию из `src/`; не создавать расходящиеся копии формул в ноутбуках. Размещать ноутбуки в `notebooks/`, проверки в `tests/`, протоколы и отчёты в `docs/`.
- Фиксировать до итоговой оценки гипотезы, основную метрику, разбиения по датам, правило выбора модели, бюджет настройки и план статистического сравнения. Отклонения документировать; анализ, выбранный после просмотра результатов, обозначать как разведочный.
- Сохранять хронологию доступности данных. Тест не использовать для настройки, выбора seed, чекпойнта, формулы штрафа или публикации только удачных вариантов. Уже использованный для настройки тест считать частью разработки; для подтверждения нужен новый нетронутый период либо явное ограничение вывода.
- Сравнивать варианты на одинаковых данных, комиссиях, ограничениях портфеля, бюджете обучения и правилах оценки. Различие регуляризации задавать явно; остальные различия обосновывать как отдельные факторы.
- Штраф за оборот в reward не является брокерской комиссией. Финансовые результаты рассчитывать по стоимости портфеля после фактических моделируемых издержек; регуляризацию показывать отдельно.
- Сохранять происхождение и версии данных, point-in-time ограничения, конфигурации, seed, зависимости и артефакты Colab. Не обещать побитовую воспроизводимость GPU без подтверждения.
- Для замечаний приводить проверяемое свидетельство: файл и строку, ячейку, конфигурацию или артефакт. Отсутствие свидетельства обозначать «не проверено», а не «ошибок нет». Не делать вывод о превосходстве стратегии по единственному удачному запуску.
- Не менять согласованный научный протокол молча. Исправления, меняющие постановку или интерпретацию сравнения, описывать с последствиями для повторного запуска.
